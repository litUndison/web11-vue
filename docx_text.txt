## Задание 1: Публикация сайта и интеграция рекламного блока
### Контекст задания
Вы завершили разработку статического фронтенд-сайта на Vue + Tailwind CSS. Теперь необходимо развернуть его на бесплатном хостинге и добавить на страницу место для рекламы. Внимание: политика разных бесплатных хостингов в отношении «размещения рекламы на сайте» существенно различается — неправильный выбор может привести к ограничению аккаунта.
### Цели задания
1. Выбрать бесплатную хостинговую платформу, соответствующую правилам, и развернуть сайт.
2. Интегрировать в сайт компонент рекламного плейсхолдера.
3. Подготовить краткий отчёт о публикации с обоснованием выбора платформы.
### Конкретные требования
**Шаг 1: Выбор платформы и оценка соответствия правилам**
Перед развёртыванием необходимо убедиться, что бесплатный тариф выбранной платформы допускает размещение рекламы. Согласно данным 2026 года:
- **Cloudflare Pages**: бесплатный тариф не содержит явных запретов на рекламу, пропускная способность не ограничена, подходит для статических сайтов с рекламой .
- **GitHub Pages**: допускает монетизацию личных или проектных сайтов (включая AdSense, спонсорские баннеры), но запрещает использование Pages в качестве платформы, «ориентированной главным образом на коммерческую деятельность или рекламу» . Обычные проектные сайты с умеренной рекламой обычно допустимы, но существует «серая зона».
- **Netlify**: представители службы поддержки заявляли, что бесплатный тариф разрешён для коммерческого использования, но это не закреплено официально в условиях обслуживания; кроме того, с 2026 года бесплатный тариф перешёл на модель кредитов (300 кредитов/месяц), а не на фиксированный лимит трафика .
- **Vercel**: тариф Hobby запрещает коммерческое использование, размещение рекламы может быть квалифицировано как коммерческая деятельность, что создаёт риск для аккаунта.
**Рекомендуется выбрать Cloudflare Pages** — как наиболее удобный вариант с точки зрения соответствия правилам и пропускной способности. Альтернативный вариант — GitHub Pages (при условии, что сайт остаётся в рамках «личного/проектного» позиционирования).
**Шаг 2: Развёртывание сайта**
1. Проверьте конфигурацию `base` в `vite.config.js` (при использовании поддомена Cloudflare Pages `*.pages.dev` можно оставить значение по умолчанию `/`).
2. Отправьте код в репозиторий GitHub.
3. Войдите в панель управления Cloudflare, перейдите в сервис Pages, подключите репозиторий.
4. Настройте сборку: Build command — `npm run build`, Output directory — `dist`.
5. Запустите развёртывание и запишите полученный URL.
**Шаг 3: Добавление компонента рекламного блока**
Создайте в проекте Vue компонент `AdSlot.vue` со следующими требованиями:
- Стилизация через Tailwind, область плейсхолдера с пунктирной рамкой и светлым фоном.
- Текстовый идентификатор (например, «Рекламное место» или «Advertisement»).
- Настраиваемый размер (через props для передачи ширины/высоты или предустановленные размеры типа `banner` / `sidebar`).
- Разместить хотя бы в одном месте страницы (например, в боковой панели главной страницы или между списками статей).
Пример структуры:
```vue
<template>
  <div class="flex items-center justify-center border-2 border-dashed border-slate-300 bg-slate-50 rounded-lg" :style="{ width, height }">
    <span class="text-sm text-slate-400">Рекламное место</span>
  </div>
</template>
```
**Шаг 4: Материалы для сдачи**
- Ссылка на сайт.
- Название хостинговой платформы и обоснование выбора (2–3 предложения).
- Фрагмент кода `AdSlot.vue`.
- Скриншот с фактическим расположением рекламного блока на странице.
### Критерии приёмки
- Сайт доступен, стили Tailwind и взаимодействие Vue работают без ошибок.
- Рекламный блок визуально чётко identifiable на странице.
- Обоснование выбора платформы и описание политики в отношении рекламы логически согласованы.

## Задание 2: Сравнительный анализ бесплатных хостинговых платформ
### Контекст задания
Перед публикацией статического сайта на Vue на бесплатном хостинге необходимо провести систематический анализ основных вариантов. Платформы существенно различаются по пропускной способности, количеству сборок, политике коммерческого использования, совместимости с рекламой и другим параметрам, и выбор напрямую влияет на устойчивость проекта.
### Цели задания
Подготовить сравнительный аналитический отчёт, охватывающий как минимум 4 бесплатные платформы статического хостинга, и дать чёткую рекомендацию для сценария «статический сайт на Vue + возможное размещение рекламы».
### Платформы для сравнения
Выберите как минимум 4 из следующего списка:
- Cloudflare Pages
- Vercel
- Netlify
- GitHub Pages
- Render (раздел статических сайтов)
### Параметры анализа
| Параметр | Описание |
|----------|----------|
| Бесплатная пропускная способность/трафик | Ежемесячный лимит или безлимит |
| Количество/длительность сборок | Ограничения бесплатного тарифа на сборку |
| Политика коммерческого использования | Разрешены ли коммерческие проекты |
| Политика в отношении рекламы | Разрешена ли сторонняя реклама на бесплатном тарифе |
| Собственный домен + SSL | Бесплатная поддержка |
| Автоматическое развёртывание из Git | Поддержка автоматической сборки из GitHub |
| Подходящие сценарии | Краткое описание в одном предложении |
### Требования к структуре отчёта
1. **Сравнительная таблица**: представьте горизонтальное сравнение вышеуказанных параметров в таблице, с указанием источника данных или обоснования.
2. **Предупреждение о рисках политики**: выделите, на каких платформах комбинация «бесплатный тариф + реклама» создаёт риски по условиям. Например, GitHub Pages разрешает умеренную монетизацию, но запрещает использование Pages в качестве основной платформы для рекламы ; Cloudflare Pages в условиях бесплатного тарифа не содержит аналогичных запретительных положений ; Netlify имеет заявления сотрудников о разрешении, но они не включены в официальные условия .
3. **Рекомендация**: для сценария «статический сайт на Vue + возможное размещение рекламы» укажите предпочтительную платформу и альтернативную, обоснуйте в 3–5 предложениях. Обоснование должно охватывать безопасность с точки зрения политики, достаточность бесплатных лимитов и совместимость с рабочим процессом Vite/Vue.
4. **Обоснование решения**: перечислите 2–3 наиболее важных для вас фактора при выборе (например, приоритет соответствия правилам размещения рекламы, приоритет пропускной способности, приоритет интеграции с Git) и объясните, почему эти факторы важны для данного сценария.
### Критерии приёмки
- Сравнительная таблица содержит полную информацию, охватывает как минимум 4 платформы.
- Раздел о рисках политики содержит ссылки на конкретные положения или надёжные источники.
- Рекомендация чёткая, обоснование согласуется с данными сравнения, отсутствуют расплывчатые формулировки.
- Объём отчёта: 600–1000 слов (без учёта таблицы).
